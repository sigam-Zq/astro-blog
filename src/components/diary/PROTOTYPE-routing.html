日记路由跳转：当前实现 vs 建议方案

这个原型要回答的问题：在 /diary/ 里，浏览器的「后退 / 前进 / 刷新」和页面里的「← 返回」「保存后离开」「删除」等按钮组合起来用时，你会不会被带到意料之外的页面（来回跳、死链、空白新建页、意外离开）？建议方案修好了这些问题吗？还会带来新的别扭之处吗？

左右两栏同时接收同一组操作。左边忠实模拟当前 DiaryApp.tsx 的 go / navigate / popstate 逻辑，右边是建议方案。每次点击后，变化的字段会被高亮。日记数据只在内存里，刷新本页即可重置。

范围：只看路由跳转。登录/会话过期和网络失败不在这里；界面 UI 优化会单独做一个可切换多套方案的 UI 原型。
