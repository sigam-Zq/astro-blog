# 私密日记 mTLS 需求

状态：需求整理，供后续生成实施计划；本文不确定证书工具、代理产品或配置步骤。

- 目标：加密日记访问链路，验证服务器身份，并通过 mTLS 限制只有持有受信任客户端证书的设备才能访问日记模块。
- 身份验证分两层：先验证设备证书，再进行账号密码登录；设备证书不能替代登录、会话和接口权限校验。
- 使用自建私有 CA 签发客户端证书，每台设备独立证书和私钥，支持新增设备、证书到期更新及丢失设备禁用。
- 服务器证书必须经过客户端严格验证。优先考虑公开受信任 CA 签发；若也使用私有 CA，需在使用设备中正确安装信任根，不以忽略证书错误代替信任配置。服务器证书来源待实施前确认。
- 日记专用域名作为候选入口，日记页面与 API 保持同源；公开博客不要求客户端证书。最终域名和入口部署方式在后续计划中确定。
- 未提供、已过期、不受信任或已禁用的设备证书不得访问日记入口；后端不能存在绕过证书验证的公网入口。
- 浏览器至入口、跨主机的入口至 Go，以及 Go 至 OSS 的网络链路均需加密并验证对端；同机进程间可以使用受限的本地通信。
- CA 私钥、服务端私钥、客户端私钥不进入前端资源、代码仓库或日志；CA 私钥离线保管，运行时只分发必要证书与私钥。
- 防护边界：抵御网络窃听和未授权设备访问；无法阻止已授权设备上的开发者工具、会话密钥导出或设备被控制后的明文读取。

待确认：使用设备及浏览器范围、服务器证书来源、专用域名、证书吊销与更新方式，以及入口和 OSS 的部署条件。
